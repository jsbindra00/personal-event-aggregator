Original application source at `e5356c82af2c1d5b1752b94a2801eb1ee940c31b` and its pnpm lock remain outside this test. Application imports and D1/D2 remain deferred.

Root must review the exact commit and commands, recheck account/repository/current production linkage and included hosted compute, verify branch Git-trigger effects, and authorize one diagnostic push before execution. The workflow accepts only a push to `codex/cloudflare-personal-event-probe` in `jsbindra00/personal-event-aggregator` by `jsbindra00`; no default-branch merge or dispatch registration is needed. Do not blindly replay a failed run or publish local planning/provenance/reports.

The source seal hashes all public payload leaves except its own file; its own identity is bound by the reviewed Git commit. Sparse filtered public Git acquisition fetches the exact pushed commit and checks out only this directory and the one workflow. The controller creates an exact copied build context after checking those hashes; `.git`, `.env`, npm config, host credentials and other repository files never enter it. A root `.env` is deliberately ignored, while unexpected files inside the probe directory fail the staging gate. Public dependency evidence contains only public registry/package identities, lock integrity, graph counts and selected native paths.

The controller's explicit acquisition and image-commit argv pin the Node Linux amd64 base by immutable digest; no Docker build is used. The sole online package operation is trusted bundled `npm ci --ignore-scripts --include=optional --no-audit --no-fund`, plus trusted `npm cache verify`, using the exact unchanged proposed lock, a task-owned cache, distinct empty task-owned regular user/global config files and an empty environment. Before the first npm invocation, trusted standard-library setup exclusively creates `/acquisition-config/user.npmrc` and `/acquisition-config/global.npmrc` inside the acquisition container and verifies zero bytes, ownership, regular non-symlink files, private modes and different inodes. Existing config paths are never reused or truncated; no real user/global npmrc is read or host config changed. All npm invocations receive those distinct paths under `env -i`, and the final verifier rechecks them before recording bundled npm version. The acquisition container uses bridge networking as its explicit egress method; registry identities are restricted by the frozen lock/preflight validator and npm SRI verification. It is not described as an OS-level registry firewall. No installed package entrypoint or lifecycle runs in acquisition. One exact named, labelled container receives the sealed context by `docker cp`; its only execution is the trusted Node keeper, the standard-library preflight/verifier, and bundled npm through explicit `docker exec env -i` commands. The controller observes a clean `stop`, `wait`, exited state and empty active-exec set before one `docker commit` creates the runtime image. No intermediate build images, build caches or host-mounted dependency volumes are created. No custom resolver, downloader or installer is used. The actual bundled npm version, complete installed package locations and versions, glibc and frozen extracted-file hashes are recorded. Optional musl/glibc metadata remains unchanged; unused optional features remain untested. Install obligations come from the tooling root and each actually installed consumer, using dependency and required-peer edges at the frozen Node lookup locations. Optional dependencies override same-name ordinary edges; absent optional peers and metadata-only peers create no required edge. Inherited per-entry optional flags do not define requiredness for this pruned graph: the omitted FreeBSD/WebContainers WASM branches alone reference hoisted `tslib`, which becomes required if either consumer branch is installed. Every installed package still requires its exact lock path/version, and the three explicit Linux x64/glibc native payload gates are unchanged. Missing required native payload or any non-lock installed package fails rather than triggering a fallback. The bounded public installed/omitted inventory is emitted before validation so an acquisition failure preserves the actual package-set diagnostics.

The resulting single committed image is frozen; its exact image ID and label are recorded. A separate offline container uses `network=none`, UID/GID 10001, read-only root and input mount, no capabilities, no-new-privileges, private PID/IPC/network/mount namespaces, two CPUs, 2 GiB memory with no added swap allowance, 256 PIDs and bounded noexec tmpfs. Its effective process environment is exactly the six reviewed assignments; inherited Node/Yarn image version variables are absent. Docker inspection must contain those same assignments plus exactly the two bare `NODE_VERSION` and `YARN_VERSION` unset markers emitted by this launcher. Unknown bare names, duplicates, missing entries and any assignment to either unset name (including an empty value) fail. The independent entry check still rejects either name in `process.env` and any other extra, missing or changed effective assignment. Only a controller JSON file is mounted, read-only. Standard input is DEVNULL and bounded stdout/stderr pipes are the only passed host streams. The Python launcher sets `close_fds=True`, passes no FDs and never mounts the Docker socket, host sockets or credentials. Actual started Docker inspection is written into the control file before the entry barrier opens; this launch-only record then stays fixed. Trusted entry checks run before any Miniflare import.

The controller owns a live TCP/HTTP and UDP canary outside the offline namespace. It tests liveness before and after runtime and records receiver receipts; UDP send success does not imply connectivity. The DNS-shaped query targets only that owned resolver. A live Unix sentinel remains outside all mounts, and the runtime asserts its path is absent. Entry records actual descriptor targets, interfaces, IPv4/IPv6 routes and namespace identities. Pipes paired inside Node and ordinary Node event/timer descriptors are permitted; an unclassified descriptor or socket is a failure. Positive controls independently exchange data through owned loopback HTTP, Unix socket and child pipes inside the offline container. These finite controls and launch attestations describe the tested boundary; there is no universal syscall-denial claim and no real cloud metadata query.

Each fixture case runs in a separate bounded child with its own Miniflare instance, using the pinned exported `convertV4MiniflareOptions` bridge and tooling-anchored module resolution. The required Linux x64/glibc workerd executable, Sharp addon and libvips paths actually loaded are hashed against the frozen image files. Workerd child executables are observed through `/proc`. Native startup is not presumed accepted merely because the lock contains those paths.

The exact synthetic HTTPS URL/method/status/body and ledger are checked. Unknown host, path and verb cases catch Worker errors deliberately, but the outbound-service denial latch still forces each child to exit 2 with an expected-failure terminal. An independent wrong-result assertion must also exit 2. Redirects use manual behavior and an exact single-call ledger; there is no real-fetch fallback. Unexpected failure or incomplete disposal exits 1 and cannot satisfy an expected-negative case. The parent retains each parsed case terminal, bounded stderr and malformed/partial-output diagnostics before any acceptance assertion, so failed native/API/transport/disposal observations remain reviewable. Canary liveness and receiver evidence are written during cleanup independently of runtime exit status, including nonempty failure ledgers.

A small pending stream and first chunk are exercised. `dispatch-cancel` reports `OBSERVED` or `NOT_OBSERVED` for its signal seam and explicitly does not claim transport propagation. Two separate owned real loopback HTTP cases destroy the client before a first chunk and after the first chunk; both require the Worker stream cancellation callback's synthetic marker. Unsupported real transport cancellation fails those cases. There is no host AbortController callback substituted as transport proof. Every case disposes Miniflare, checks its owned workerd PID exits and verifies its listener refuses connections; child natural exit also detects outstanding timers/handles. Watchdog killing is a failure, never successful disposal.

`controller.py` applies acquisition/offline/collection deadlines of 5/12/3 minutes within one Ubuntu job capped at 20 minutes. Source checkout and upload also consume that hard job cap, so a job-level timeout may leave incomplete evidence and can never pass. Controller cleanup attempts each owned resource independently. It kills any interrupted acquisition execution within the exact labelled acquisition container, waits for its exit and observes no active exec before removing it. It removes only the exact owned committed image and runtime container, closes canary sockets/threads and removes the exact scratch directory; the shared pinned base and unrelated resources are preserved. Missing final-tag output alone never proves cleanup: unknown create, pull or commit completion explicitly fails that gate. A missing native binary, beta API, cancellation signal or inspection field is a failed gate for review; no repair, dependency resolution or retry path is included.

All command stdout/stderr together are capped at 256 KiB, tighter than the 1 MiB runtime ceiling. Terminal JSON is at most 64 KiB. Only the listed JSON/log evidence files and their hash manifest may be collected, with an aggregate 512 KiB ceiling. Binary files, source trees, dependencies, caches and archives are not exported. Raw evidence is never an upload path. A separate finalization step snapshots and validates regular allowlisted bytes, writes and verifies a matching final manifest in a private staging directory, then atomically exposes the upload-ready directory. The action is gated by a readiness output emitted only after final-byte revalidation. Collection rejection creates a fresh bounded `FAIL` bundle from safe diagnostic leaves, or suppresses upload if that bundle cannot be verified; rejected files and stale PASS manifests cannot reach the upload action. Failure manifests match their final controller bytes and explicitly name omitted raw diagnostics. Complete success requires every evidence leaf, complete JSON/terminal records, exact ledgers, no violations and successful disposal. Root must verify the artifact manifest before any download, with the separate authorized compressed/unpacked limits.
